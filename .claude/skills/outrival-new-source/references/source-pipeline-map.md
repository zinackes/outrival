# Source pipeline map — exact files, anchors, worked examples

Companion to `../SKILL.md`. Referenced by **symbol/anchor**, not line number, so it
survives edits. Everything below was extracted from the live `sitemap` + `news`
sources (patch-32).

## The end-to-end flow

```
competitor created ──► provisioning seeds monitors (incl. INTERNAL sources, weekly)
        │
[cron hourly] schedule-scraping ──► scrape-monitor.job.ts (per due monitor)
        │
        ├─ getScraper(sourceType)            packages/scrapers/src/index.ts
        ├─ scrape() → ScrapeOutcome          packages/scrapers/src/<source>/<source>.scraper.ts
        ├─ upload R2 (before DB)             done by the job, not the scraper
        ├─ insert snapshot                   completeness gate → success | partial
        ├─ generic diff (sorted body)        no per-source code for list sources
        └─ change → classify-change → generate-signal
```

A "sorted-list" source (sitemap/news) adds **nothing** to `scrape-monitor.job.ts`
except membership in `SIZE_VARIABLE_SOURCES`. Everything else is the scraper + the
generic chain.

## The `ScrapeOutcome` contract

Return shape the scraper produces (`packages/scrapers/src/types.ts`). For a
list/feed source, the browser-only fields are inert:

```ts
{
  html,                    // the diff-bearing body: sorted entries, 1 per <li>/line
  text,                    // "summary\n" + entries.join("\n") — the plaintext the diff reads
  screenshotBuffer: Buffer.alloc(0),   // no screenshot for a feed source
  metadata: { url, scrapedWith: "<source>", … },
  statusCode: 200,
  level: 0,                // L0 = pure fetch, no cascade
  attempts: 1,
}
```

## Worked example — deterministic snapshot (from `sitemap.scraper.ts`)

The body is a **sorted URL list** plus a stable category-count header. The `+`/`-`
diff of two runs is exactly the added/removed pages:

```ts
function buildSnapshot(rootUrl: string, urls: string[]): ScrapeOutcome {
  // Stable header — moves only when the category mix changes.
  const counts = new Map<UrlCategory, number>();
  for (const u of urls) counts.set(categorizeUrl(u), (counts.get(categorizeUrl(u)) ?? 0) + 1);
  const summary = Array.from(counts.entries())
    .sort(([a], [b]) => a.localeCompare(b))
    .map(([cat, n]) => `${cat}: ${n}`).join(", ");

  // Diff-bearing body: one URL per line, ALREADY SORTED → +/- lines map 1:1.
  const list = urls.map((u) => `<li>${escapeHtml(u)}</li>`).join("");
  return {
    html: `…<ul>${list}</ul>…`,
    text: `${summary}\n${urls.join("\n")}`,
    screenshotBuffer: Buffer.alloc(0),
    metadata: { url: rootUrl, scrapedWith: "sitemap", urlCount: urls.length },
    statusCode: 200, level: 0, attempts: 1,
  };
}
```

## Worked example — fail loud, never empty (from `sitemap.scraper.ts`)

```ts
for (const root of roots) {
  const urls = await collectSitemapUrls(root, { fetchBytes });
  if (urls.length > 0) return buildSnapshot(root, urls);
}
// No sitemap anywhere → THROW so Trigger retries (and the monitor can be marked
// unscrapable) rather than writing an empty snapshot the next diff reads as
// "every URL removed".
throw new Error("no_sitemap_found");
```

`news.scraper.ts` does the same on a missing brand (`throw new Error("news: no
brand …")`) and on a non-200 feed fetch. The rule: **no result ⇒ throw**, never a
zero-entry success.

## Worked example — AI-free feed leaf (from `feeds/rss.ts`)

`parseFeed(xml)` returns normalized `FeedItem[]` via pure regex (RSS 2.0 + Atom),
and returns `[]` when the payload isn't a feed — no XML dependency, no AI:

```ts
export function parseFeed(xml: string): FeedItem[] {
  if (!/<rss\b|<feed\b|<rdf:RDF\b/i.test(xml)) return [];   // not a feed → [] (never a guess)
  const isAtom = /<feed\b[^>]*xmlns=["'][^"']*Atom/i.test(xml) || /<entry\b/i.test(xml);
  const items = isAtom ? blocks(xml, "entry") : blocks(xml, "item");
  // … extract title/link/publishedAt/id/summary per item …
}
```

`news.scraper.ts` consumes it: `filterNewsItems(parseFeed(xml), brand, { withinDays })`
→ `buildNewsDoc()` → sorted snapshot. Zero AI on the per-scrape path.

## The completeness / anti-void guard (`completeness.ts`)

`assessCompleteness` grades the middle band the cascade doesn't already throw on. For
a new source, the only knob you touch is **eligibility**:

- `ratioEligible: false` for size-variable append sources — they legitimately swing.
  Set by membership in `SIZE_VARIABLE_SOURCES` (`scrape-monitor.job.ts`), currently
  `{ blog, changelog, news, sitemap }`. Add yours if it's append-y.
- A brand-new monitor is never flagged (needs `>= minPriors` prior sizes first).
